Four things a browser can do without any libraries

Each project below is one HTML file with hand-written JavaScript — no framework, no build step, no dependencies. They cover the parts of front-end work I find most interesting: application state, algorithms, pixels, and sound.

Behind them sits one Node server built the same way, from node: builtins only: its own router, its own PNG and WAV encoders, its own WebSocket implementation, and worker threads for the heavy work. Open any app without it and everything still runs; start it and each app gains a backend.

Shelf — stock control

An inventory tool for a small retail shop: reorder alerts, sortable columns, CSV import and export, and an undo that actually works. Data lives in the browser.

With the server: SQLite storage, live sync across tabs, stock movement log.

State & datalocalStorageCSV parserSQLiteWebSocket

Pathfinder — search visualizer

A*, Dijkstra, breadth-first, greedy and depth-first running on the same grid, so you can see how much of the map each one bothers to look at. Includes a maze generator and weighted terrain.

With the server: all five benchmarked over seeded mazes in a worker pool.

AlgorithmsCanvas 2DBinary heapworker_threads

Image Lab — pixel processing

Brightness, contrast and gamma through a lookup table; blur, sharpen, emboss and Sobel edges through hand-written 3×3 convolution. Live RGB histogram and a before/after split.

With the server: full-resolution pass in a worker, PNG from a hand-written encoder.

GraphicsImageDataConvolutionPNG encoder

Pulse-16 — step sequencer

A drum machine that ships no audio files: every kick, hat and clap is built from oscillators and noise at play time, scheduled ahead of the clock so the timing holds steady. Patterns save into the URL.

With the server: offline WAV render, saved patterns, live jam room.
